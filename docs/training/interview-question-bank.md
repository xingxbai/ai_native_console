# Day 12：工具契约与描述

- 问：`optional` 和 `nullable` 有何不同？答：可选字段可以省略；可空字段存在时可以是 `null`。订单状态视图省略退款原因，订单 133 的退款原因为 `null`。追问：模型回答时如何区分“未查询”与“查询结果为空”？看字段是否存在及业务语义。
- 问：`orderId` 通过 Zod 是否证明用户有权查询？答：不能，Schema 只验证格式，权限要在服务端根据身份、租户和订单归属判定。追问：为什么不能交给模型决定？模型的选择不是可信授权决策。
- 问：工具描述如何帮助模型选对工具？答：写清适用场景、必填参数、限制和不适用条件，再用真实问题核对工具调用记录。追问：最终答案正确是否足够？不够，模型也可能未调用工具而猜测。

## Day 14：有界工具参数纠错

- 问：`stepCountIs(2)` 是否限制修复两次？答：不是，它限制主模型步骤；`repairAttempts` 单独限制额外修复调用为一次。追问：修复消耗 token 吗？会，额外的模型调用有输入和输出成本。
- 问：为什么只修错误的 `view`，不修缺失的订单号？答：`view` 是可选枚举，订单号是业务目标；缺编号时模型不能凭空猜测。追问：修复后为什么还比对订单号？防止修复过程改变查询对象。
- 问：权限拒绝可以让模型换参数重试吗？答：不能，权限是服务端最终决定，不属于可恢复格式错误。追问：所有工具错误统一重试有什么风险？可能绕过授权、重复副作用并放大成本。

- 问：为什么 503 可以有限重试，400 不重试？答：503 通常是暂时性故障；400 原样重试通常仍会失败。追问：429 如何处理？参考 `Retry-After` 并限制重试预算；本课固定等待 200ms。
- 问：工具超时后可以直接重试修改订单吗？答：不能，首次写入可能已成功但响应丢失；需要稳定幂等键和执行状态。追问：取消请求能回滚吗？不能。
- 问：如何区分模型故障和工具故障？答：在执行边界使用不同错误类型和 SSE 错误码，页面显示对应文案，服务端用请求 ID 关联日志。追问：能把外部接口原始异常展示给用户吗？不能，可能泄露内部信息。

## Day 16：前端 ContextCollector

完整回答、追问和错误答案见 [Day 16 课件](lessons/day-16-frontend-context-collector.md)。

- 问：为什么只传订单 ID，不传整页 DOM？答：任务只需定位记录；整页包含无关内容、敏感信息和注入风险。追问：可见的客户姓名能发吗？默认不发，除非任务和授权需要。
- 问：前端已校验，API 为什么还要校验？答：请求可被伪造，服务端必须独立校验结构并在工具层鉴权。追问：Schema 通过等于有权查询吗？不等于。
- 问：切换订单如何避免旧上下文？答：筛选变化清空选择，每次提交重新采集页面状态。追问：浏览器切换已验吗？本课尚待手动验收。

## Day 17：Token 预算与上下文裁剪

完整回答、追问和错误答案见 [Day 17 课件](lessons/day-17-token-budget.md)。

- 问：为什么不能只看用户输入长度？答：指令、上下文、工具 Schema、工具结果和输出都占空间。追问：粗估能当费用吗？不能。
- 问：预算不够先删什么？答：先删筛选，再删选中 ID；核心规则和用户问题超预算则拒绝。追问：丢失 ID 后怎么回答“这条订单”？要求明确编号。
- 问：怎样证明省 Token 没损害回答？答：比较工具选择、参数和最终答案，并记录真实用量；本课尚未做模型对照。追问：仅估算下降够吗？不够。

- 问：为什么按完整问答对裁剪？答：拆开会形成无来源答案或无回答问题；工具调用未来也必须成组。追问：本课有工具历史吗？没有。
- 问：摘要与数据库事实区别是什么？答：摘要只是旧对话语境，当前业务事实要重新查工具。追问：冲突时信谁？信当前授权查询结果。
- 问：目前能跨设备恢复吗？答：不能；历史在页面内，每次随请求提交，没有持久会话存储。追问：history 字段等于记忆吗？不等于。

## Day 19：Prompt Injection 与数据最小化

完整回答、追问和错误答案见 [Day 19 课件](lessons/day-19-prompt-injection.md)。

- 问：历史或工具结果里的“忽略规则”能当指令吗？答：不能；它们是不可信数据，权限由服务端判断。追问：system prompt 能保证不被注入吗？不能。
- 问：为什么用户信息工具只给模型三个字段？答：只传当前任务需要的身份字段，邮箱等无关字段不进入模型。追问：用户要邮箱怎么办？需要单独受控查询设计。
- 问：四个正则脱敏样例通过代表安全了吗？答：不代表；只覆盖已知格式，变形值和其他 PII 仍可能漏。追问：真实模型注入测过吗？尚未。

## Day 20：会话隔离、并发与重复请求

完整回答、追问和错误答案见 [Day 20 课件](lessons/day-20-session-concurrency.md)。

- 问：`requestId` 与 `requestKey` 区别？答：前者追踪日志，后者识别一次提交意图。追问：重复键会重放结果吗？不会，当前返回 409。
- 问：如何处理同会话并发？答：前端 ref 和服务端会话占位双层拒绝；不同会话独立。追问：多进程共享吗？当前不共享。
- 问：现在实现真实租户隔离和写操作幂等了吗？答：没有登录归属或持久记录，只是单进程演示。追问：真实改订单需要什么？身份、授权、持久幂等和审计。

## Day 21：StateGraph、Node、Edge 与条件路由

完整推荐回答、追问与错误答案见 [Day 21 课件](lessons/day-21-stategraph-routing.md)。

- 问：State、Node、Edge 各负责什么？答：State 保存运行数据，Node 更新局部字段，Edge 决定后续节点。追问：两分支为什么用图？为后续工具、审批和恢复建立显式流程；当前 `if` 也足够。
- 问：如何阻止非法分支和无限循环？答：Zod 限定输入，条件边只映射两路，分支连 END，并设置 recursionLimit。追问：上限为 1 时怎样？已观察到 `GraphRecursionError`。
- 问：LangGraph 与 AI SDK 目前各管什么？答：图只做订单查询路径规划，AI SDK 仍处理现有 DeepSeek 请求与流；两者尚未接在一起。追问：图已查订单了吗？没有。
