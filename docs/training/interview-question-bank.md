| 题目 | 关键回答 | 追问 |
| --- | --- | --- |
| 为什么先搭可运行骨架而不是直接写 Agent？ | 先固定环境、前后端边界和测试，便于后续定位 HTTP、模型与工具故障；目前只验证静态页和 health。 | health 200 能证明模型/数据库可用吗？不能。 |

| 怎样审查 AI Coding 生成的脚手架？ | 先读现有文件与规则，再查依赖、秘密、失败路径；跑 lint/typecheck/test/build，最后真实请求。 | 四项命令全绿还需手动看页面吗？需要，运行和视觉风险未被完全覆盖。 |

## Day 02：开发环境、API 契约与错误边界

完整推荐回答、追问回答和错误答案分析见 [Day 02 课件](lessons/day-02-api-contracts.md)。

| 题目 | 核心回答 | 追问 |
| --- | --- | --- |
| TypeScript 已经有类型，为什么还要 Zod？ | 编译期类型不能验证环境变量和网络返回；Web/API 共用运行时 Schema，并分别在边界解析。 | 共享类型能保证独立部署永远兼容吗？不能，仍需运行时校验。 |
| 如何设计统一错误体和 requestId？ | 400/404/500 共用 `error.code/message/requestId`；服务端生成 UUID，头体一致，500 不暴露内部文本。 | requestId 能代替鉴权或幂等键吗？不能。 |
| API 不可达时页面如何处理？ | Next 服务端检查状态、Schema 和 UUID，2 秒内失败则在页头显示“API 暂不可用”；提问失败另有错误态。 | health 200 能证明模型可用吗？不能。 |

**证据边界：** Day 02 当时完成 25/25 测试、lint/typecheck/build、真实 HTTP 200/400 和页面“已连接”；浏览器离线/恢复交互未自动化。聊天入口和模型错误映射已在后续 Day 04 增加。

## Day 03：DeepSeek 模型服务适配

历史完整答案见 [Day 03 课件](lessons/day-03-deepseek-provider.md)；当前实现已按用户决定改为 DeepSeek-only，以下以当前代码为准。

| 题目 | 核心回答 | 追问 |
| --- | --- | --- |
| 只有 DeepSeek 时为什么仍保留服务端 provider 边界？ | 把 SDK 调用、20 秒上限与 1024 token 限制留在 Node 侧，HTTP 层只处理契约和错误。 | 这是否意味着已有多供应商降级？没有。 |
| 为什么密钥只能放在服务端？ | 浏览器变量可见；本地密钥文件被 Git 忽略、权限 600，不进入日志或返回值。 | 已出现在对话中的 Key 应怎样处理？轮换。 |
| 如何证明 DeepSeek 接入可用又不过度宣称？ | 当时真实短回复返回 `OK`；当前同源入口也实际返回 `OK`。当时的 8 个测试已不等于当前测试数；一次结果不能证明长期可靠。 | health 200 能证明模型可用吗？不能。 |

**证据边界：** 当时的课程曾有模拟分支，现已按用户要求删除；当前只有 DeepSeek 服务端接入。真实 401/429 等供应商错误仍未逐项验证，也没有 Agent 或生产 SLA。

## Day 04：第一次非流式 LLM 调用

完整推荐回答、追问回答及错误答案分析见 [Day 04 课件](lessons/day-04-first-llm-call.md)。

| 题目 | 核心回答 | 追问 |
| --- | --- | --- |
| system、user、assistant 在当前调用链各在哪里？ | API 固定 `instructions`，校验用户 `prompt`，完整文本封装为 assistant；没有多轮历史。 | system 指令能保证业务结论真实吗？不能。 |
| 超时、供应商错误与空输出如何区分？ | 20 秒 deadline、1024 输出 token、关闭默认思考模式、零自动重试；超时/异常/空或截断输出分别映射 504/503/502。 | 浏览器断连会自动取消模型和费用吗？本课未验证。 |
| 如何证明当前页面真正调用了 DeepSeek，又不过度宣称？ | 响应固定标注 `provider=deepseek`，同源入口两次实际得到 `OK` 与 `4`；样本太少，不代表稳定性或通用质量。 | 页面 200 是否足够？还要核对响应内容与来源。 |

**证据边界：** 当前已删除模拟模型专属旧测试文件，保留的 21 个测试通过；没有新增或修改 `.test.ts`。问答接口通过真实 HTTP 与 DeepSeek 两个短答样例验收；浏览器自动点击、真实 401/429/超时、长期性能和模型质量未验证。

## Day 05：SSE 流式协议

完整口头回答、追问回答和错误答案分析见 [Day 05 课件](lessons/day-05-sse-streaming.md)。

| 题目 | 核心回答 | 追问 |
| --- | --- | --- |
| 网络 chunk、SSE 帧和模型 token 为什么不能画等号？ | chunk 是任意字节段；SSE 以空行组帧；token 是模型生成单位。本课真实流按 1–20 字节切开仍得到同一正文。 | 半个汉字怎么处理？用增量 UTF-8 解码。 |
| 为什么当前用 POST fetch + SSE？ | 问题在 JSON body 中，`fetch` 可提交 POST 并读取流；EventSource 主要用 GET，WebSocket 双向能力暂不需要。 | 有 `id` 就能重连吗？不能，当前没有事件存储与重放。 |
| HTTP 200 后模型出错怎么办？ | 头部已发，流中用 `error` 事件；客户端只在 `done` 后确认完成，截断 EOF 拒绝。 | 关闭浏览器能停模型吗？当前不能保证，Day 07 再验证。 |

**证据边界：** 真实 DeepSeek SSE、20 种拆分、慢读和异常 EOF 已操作验收；21/21 个旧测试不覆盖新流。浏览器自动点击、真实供应商中途断流、取消传播和重连未执行。
