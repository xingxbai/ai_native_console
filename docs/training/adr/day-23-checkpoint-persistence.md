# Day 23 ADR：图状态持久化边界

状态：方案记录，尚未实施生产持久化。

## 决策

本地课程用 LangGraph `MemorySaver` 理解 checkpoint 与 `thread_id`；生产部署若需要暂停后跨进程恢复，采用数据库支持的持久 checkpointer，并把线程归属、租户、审批记录和审计事件存入服务端数据库。此阶段不引入数据库依赖。

## 原因与约束

- `MemorySaver` 只在当前 Node 进程内保存状态。重启或请求落到另一实例，旧 checkpoint 不存在。
- `thread_id` 是查找 checkpoint 的键，不是登录凭证。读取、恢复前先由服务端根据认证身份核对 owner、tenant 和线程归属；不能接受浏览器自称的 owner。
- 图状态可能包含订单数据、模型输入和工具结果。生产存储要限制保留字段、加密和清理期限；日志不打印完整 checkpoint。
- 聊天消息、图 checkpoint、待审批记录和 SSE 事件各有不同职责。只保存聊天消息不能恢复图节点；只保存 checkpoint 也不能自动补发断线期间的 UI 事件。
- 写操作恢复还需持久幂等键、审批人/参数版本和二次权限校验。Day 24–25 再实现审批与 resume，Day 30 再处理事件恢复。

## 进入生产前的验收

在独立进程或多实例上完成写入后，重启并以同一授权身份读取和恢复；不同线程、不同 owner/tenant 均不能读；并发恢复只能有一次有效执行。当前 Day 23 命令只能证明 `MemorySaver` 的局限，不能证明上述能力。
