## 1. 真实场景与目标

运营人员问：“2026-10-28 到 2026-10-31 各运营商处理失败率是多少？”模型负责理解问题和解释结果，服务端工具负责按租户、日期、省份过滤并聚合。统计口径固定为：**一条事件是一次处理尝试，失败率 = 失败尝试数 / 全部尝试数**。无记录时失败率为 `null`，不能写成 0%。演示数据不是线上业务指标。

## 2. 重点代码与操作

`apps/api/src/data/analytics-events.json` 模拟统计系统返回，包含不同日期、省份、运营商、状态、失败代码和另一租户的隔离记录。`apps/api/src/business-analytics.ts` 统一解析日期和源数据；实际企业项目可把 `readFile` 换为有参数绑定的 SQL/内部 API 查询，仍保留服务端权限过滤和口径函数，不允许模型拼接 SQL。

```ts
const records = data.records.filter((item) => item.tenantId === actor.tenantId
  && actor.allowedProvinces.includes(item.province)
  && item.date >= query.from && item.date <= query.to
  && (!query.province || item.province === query.province));
```

`getOrderMetrics` 返回总尝试、失败尝试和失败率；`getOperatorMetrics` 按移动/联通/电信分组；`getFailureBreakdown` 把 `TIMEOUT`、`REJECTED` 映射为“超时”“上游拒绝”。三者只读。模型工具描述要求用户明确给出起止日期、不得把失败原因分布说成根因。重点计算：

```ts
const failed = records.filter((item) => item.status === "failed").length;
const failureRate = records.length ? failed / records.length : null;
```

## 4. 本课专项五大深水坑

| 场景 | 错误表现 | 处理与验证 |
| --- | --- | --- |
| 分母不一致 | 把失败数除以成功数或订单金额 | 固定“全部处理尝试”为分母，7 次中失败 4 次。 |
| 日期边界错 | 少算结束当天 | ISO 日期包含起止日，10-31 的记录被统计。 |
| 无数据被说成零失败率 | 0/0 被显示为 0% | 返回 `failureRate: null`。 |
| 越权跨租户/省份 | 模型指定未授权范围拿到数据 | tenant 由服务端身份提供；不允许的省份直接拒绝。 |
| 枚举与根因混淆 | TIMEOUT 被当成已经定位网络根因 | 只映射为“超时”，输出次数，不断言原因。 |

## 6. 模拟面试

**Q1：为什么统计口径要写在工具层，而不是提示词里？** 推荐回答：模型善于选择工具和解释，但业务指标的分母、状态定义、日期边界必须由服务端确定，才能复算和版本管理。追问：模型说“失败率 57%”怎样复核？查看 `totalAttempts=7`、`failedAttempts=4` 和筛选范围，计算 4/7。错误答案：“模型看过原始数据就会算对”。

**Q2：没有数据时失败率应返回 0 还是 null？** 推荐回答：返回 `null`；0% 表示有样本且没有失败，0/0 则没有可计算比例。追问：前端怎么显示？显示“暂无数据”或破折号，并保留总数 0。错误答案：“为了图表方便写 0%”。

**Q3：如何防止模型分析到其他租户的数据？** 推荐回答：租户 ID 和允许省份由服务端认证身份确定，在实际查询前过滤；模型工具参数只表达日期和可选省份，不能自称租户。追问：如果用 SQL？使用参数绑定、行级权限或明确 tenant 条件，不能拼接模型字符串。错误答案：“提示词写‘不要越权’就足够”。
