# Day 04：第一次非流式 LLM 调用

状态：**COMPLETED**。本课的主线是把一个面试题或工程场景提交给真实 DeepSeek，并能解释每一道边界。课程实施时曾有模拟模式，现已按用户要求删除；下面以当前代码为准，末尾保留当时真实执行过的历史测试摘要。从 Day 04 起不新增或改写 `.test.ts`。

## 1. 目标、前置与真实场景

前置：Day 02 的共享 Zod 契约、错误体和 requestId；Day 03 的服务端 DeepSeek 适配。场景一是回答 Agent/Workflow、工具执行权等面试题；场景二是讨论订单审批、客服检索、模型故障等工程方案。当前只是**一次完整文本问答**，没有仓库读取、业务数据、工具调用或 Agent Loop。

完成标准：浏览器提交后得到标注来源的 `assistant` 回复；无效输入在模型前拒绝；超时、供应商失败和无效输出有稳定错误；能说清一次真实请求证明了什么、没有证明什么。

## 2. 概念与链路

`instructions` 是服务端固定的 system 约束；`prompt` 是经校验的单条 user 问题；`generateText()` 的完整 `text` 才被封装为 assistant 回复。模型文本是参考答案，不是可信业务事实或执行授权。

```text
练习表单 -> Next POST /api/chat -> Fastify POST /api/v1/chat
          -> 服务端 DeepSeek provider -> DeepSeek API
          <- assistant 文本 / 统一错误体 + requestId
```

Next 和 Fastify 都解析共享请求 Schema。Next 还验证上游响应体和 `x-request-id`；Fastify 生成 UUID，并只在服务端读取密钥。当前关闭 DeepSeek V4 默认思考模式，模型调用最多 20 秒、1024 输出 token、零自动重试；Next 代理上限 25 秒。达到长度上限的不完整答复会返回 502。API 仅允许回环地址监听，尚无登录、限流或总成本预算。

## 5. 本课专项五大深水坑

| 失效场景 | 触发、原因 | 处理与本课测试 |
| --- | --- | --- |
| system/user/assistant 混淆 | 把用户输入拼成高权限指令，或把回复当业务事实 | system 约束由 API 固定、user 单独校验；响应标记 assistant/DeepSeek。真实请求验证响应形状，复杂注入未测。 |
| 无效输入消耗额度 | 空白、超长或多余字段越过前端控件 | Next/Fastify 都用严格 Schema；两个入口的空白请求实际返回 400，501 字和多余字段由 Schema 约束但未单独 HTTP 演练。 |
| 供应商超时变成笼统 500 | 外部请求超过 deadline | `AbortSignal.timeout(20_000)` 映射 504；历史运行时故障注入得到 504，真实供应商超时未演练。 |
| 错误或空输出泄露内部信息 | 异常含敏感信息；V4 默认思考模式曾把 128/512 token 全用于 reasoning，工程题正文为空；512 token 正文也曾截断 | 异常固定 503，空/过长/截断返回 502；关闭默认思考模式并设 1024 token，历史故障注入验证脱敏与 requestId，本轮复验正文。 |
| 一次成功被误当质量保证 | 短答可用但复杂工程问题可能不准 | 评测记录分别注明样本量和观察；没有准确率、SLA、真实业务数据或长期稳定性证据。 |

## 三、模拟面试真实考场

### Q1：system、user、assistant 在这个项目中分别在哪里？

**推荐口头答案：** Fastify 固定 system 指令，用户问题经过共享 Zod Schema 后作为 `prompt` 发给 DeepSeek。AI SDK 的 `generateText()` 返回完整文本后，API 将它封装为 `assistant` 回复，附模型来源和 requestId。没有历史消息、工具或 Agent Loop。**追问：system 指令能保证回答真实？**不能，它只影响生成；业务事实需要可信数据源和服务端校验。**常见错误：**“写了 system prompt 就不会编造”，忽略了模型输出不可靠的事实。

### Q2：超时、供应商故障和空回复如何处理？

**推荐口头答案：** 模型调用 20 秒截止、1024 输出 token、关闭默认思考模式、零自动重试。明确超时返回 504，供应商异常返回 503，空、过长或到达长度上限的文本返回 502；公开响应不包含内部异常，并附 requestId。历史运行时故障注入验证部分映射，但真实 401/429 和自然超时尚未演练。**追问：浏览器断开就不会收费了吗？**不能保证；取消传播属后续课程。**常见错误：**“fetch 超时等于整个任务及副作用已取消”，混淆了不同边界。

### Q3：怎样证明它真的使用 DeepSeek，又不过度宣称？

**推荐口头答案：** 我从 Next 同源入口发真实 HTTP 请求，返回的 provider 是 `deepseek`、assistant 内容为 `OK`，头体 requestId 一致；另有两个短答样例记录。它证明当时的本地路径可用，不证明复杂题质量、持续可用性或生产 SLA。**追问：`/health` 200 足够吗？**不够，它只说明基础 API 路由可达。**常见错误：**“页面能打开就说明模型正常”，忽略了前后端与供应商是不同链路。
