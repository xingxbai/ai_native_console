# Day 27：工作流版本化与静态校验

日期：2026-11-06。状态：**IN_PROGRESS（服务端命令与路由已验，浏览器待验）**。前置：Day 26 画布草稿。本课只校验“能不能发布”，不保存、不发布、不执行工作流。

## 1. 真实场景与目标

业务人员在画布中连出 `查询 → 审批 → 查询` 的环，或者删除一个节点却留下引用它的线。React Flow 能把这些画出来，不代表后端能安全执行。发布前，服务端必须独立检查提交的 JSON，拒绝坏图；前端的即时连线限制只改善操作体验。

## 2. 重点代码与操作

服务端核心见 `apps/api/src/workflow-validation.ts`。`version: 1` 和三种节点类型由 Zod 限定；节点有 ID、标签和有限坐标，边有来源和目标。随后按 ID 建立邻接表，检查缺节点、结束节点数量、唯一入口、环路、不可达节点和无后续连线。

```ts
const parsed = workflowSchema.safeParse(input);
if (!parsed.success) return { valid: false, issues: ["版本、节点或连线格式不合法"] };
const ids = new Set(parsed.data.nodes.map((node) => node.id));
for (const edge of parsed.data.edges) {
  if (!ids.has(edge.source) || !ids.has(edge.target)) issues.push("连线引用不存在的节点");
}
```

环路检查使用 DFS 的 `active` 集合：遍历时再次遇到当前路径上的节点，即有环。浏览器的“检查流程”按钮提交 `{ version, nodes, edges }` 到 Next 同源代理，再由 Fastify 的 `POST /api/v1/workflows/validate` 调用同一校验函数。返回 `valid` 与中文 `issues`；没有写数据库，也没有调用 LangGraph。

运行 `pnpm --filter @ai-native-console/api day27:validate`，然后在已有运行环境打开 `/workflow`，添加多余节点或画回路，点击“检查流程”。

## 3. 通用五大深水坑

| 深水坑 | 本课关系 |
| --- | --- |
| 流式 / Partial JSON / Generative UI | 校验返回完整 JSON；不把模型输出当节点代码。 |
| 工具参数与自我纠错 | 工作流定义是外部输入，服务端必须解析并拒绝不合法参数。 |
| 上下文与 Token | 本课无模型调用；节点数量上限 30、边上限 60 控制处理规模。 |
| HITL 与副作用安全 | 审批节点只是定义；校验通过仍不代表已审批或有权执行。 |
| 取消、断流与恢复 | 流程定义版本和运行 checkpoint 是两种数据，互不替代。 |

## 4. 本课专项五大深水坑

| 坑 | 处理 | 验收 |
| --- | --- | --- |
| 只信前端连线限制 | 服务端重新检查完整图 | 命令直接提交环路并被拒绝。 |
| 引用已删除节点 | 边两端必须存在 | 缺失节点被拒绝。 |
| 多入口或孤立节点 | 唯一起点、起点可达全部节点 | 孤立节点被拒绝。 |
| 旧版本直接执行 | 只接受 `version: 1` | 版本 0 被拒绝。 |
| 把校验当发布 | 当前 API 只返回问题，不存储/运行 | 页面只有“检查流程”。 |

## 6. 模拟面试

**Q1：前端已经禁止自连，后端为什么还要检查环？** 推荐回答：前端请求可伪造，而且 A→B→A 不是自连。后端以实际收到的 JSON 为准，用 DFS 检测环。追问：有环一定不允许吗？本课程的线性订单流程不允许；允许循环的引擎需要单独设计终止条件。错误答案：“React Flow 不会生成坏图”。

**Q2：流程定义为什么要有版本？** 推荐回答：节点字段和执行语义会变，服务端必须知道按哪套契约解析；本课只接受版本 1。追问：版本 0 怎么办？明确拒绝或走受控迁移，不能默默猜。错误答案：“TypeScript 类型会自动兼容历史 JSON”。

**Q3：`valid:true` 能直接执行吗？** 推荐回答：不能。它只说明静态结构满足当前规则；执行还要查发布权限、节点所用工具权限、业务参数和运行时限制。追问：审批节点已经画出来了吗？画出来只是定义，运行时仍需实际中断、身份认证和 resume。错误答案：“校验通过就相当于审批通过”。
